# DjangoERP

A Django 5 + Django REST Framework ERP, built outward from a double-entry accounting core: chart of accounts, journal entries, invoices/payments, and async financial reports (balance sheet, income statement, trial balance, general ledger, cash flow).

This financial core was consolidated from [`amrs-project`](https://github.com/bamr87/amrs-project) (AMRS — Accounting & Management Reporting System), the most mature of several overlapping accounting prototypes in the fleet. See [CLAUDE.md](CLAUDE.md) for the full consolidation rationale and the domain rules that must not be broken.

## Technology stack

* **Backend:** Python 3.11, Django 5.0, Django REST Framework
* **Database:** PostgreSQL in production, SQLite by default in development
* **Authentication:** JSON Web Tokens (JWT) via `djangorestframework-simplejwt`
* **API docs:** Swagger & ReDoc (`drf-yasg`)
* **Task queue:** Celery (Redis broker); runs synchronously in dev
* **Testing:** `pytest` / `pytest-django`, plus `manage.py test`

## Getting started

```bash
python3.11 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
cp .env.example .env

python manage.py migrate            # migrations are committed — no app-label dance needed
python manage.py createsuperuser

python manage.py runserver          # http://localhost:8000/
```

Migrating seeds the five `AccountType` codes (`AS`/`LI`/`EQ`/`RE`/`EX`) that `reports/report_generators.py` hard-codes, via `coa`'s `0002_seed_account_types` data migration — a fresh database has a working chart of accounts from the start.

## Project structure

```
djangoerp/          # Project settings (base/dev/prod split), root urls, celery app
core/                # Shared abstractions (TimestampMixin) used across apps
accounts/            # UserRole (admin/accountant/viewer/auditor), AuditLog, JWT login, permissions
coa/                 # Chart of accounts: AccountType + self-referencing Account tree
journal/             # JournalEntry + JournalLine — the double-entry ledger
invoices/            # Invoice, InvoiceLineItem, Payment — AR/AP
reports/             # ReportTemplate + SavedReport, and report_generators.py (the report math)
requirements.txt
```

## API overview

| Path | Method | Description |
| --- | --- | --- |
| `/api/auth/login/` | POST | Obtain JWT access & refresh tokens |
| `/api/auth/refresh/` | POST | Refresh JWT token |
| `/api/coa/accounts/` | GET/POST | Chart of accounts; `/hierarchy/` for the tree view |
| `/api/journal/entries/` | GET/POST | Journal entries (balanced, double-entry) |
| `/api/invoices/invoices/`, `/api/invoices/payments/` | GET/POST | AR/AP |
| `/api/reports/templates/`, `/api/reports/saved-reports/` | GET/POST | Reports; `saved-reports/{id}/regenerate/` |
| `/admin/`, `/swagger/`, `/redoc/` | — | Django admin and API schema docs |

Reports are generated by creating a `ReportTemplate` with the desired `report_type` and then a `SavedReport` from it, rather than by a per-report-type endpoint.

## Consolidation roadmap

This is the first of several planned consolidation passes:

1. **Done** — core ledger (`accounts`, `coa`, `journal`, `invoices`, `reports`) ported from `amrs-project`, with `amrs-django`'s settings-split/test scaffolding adopted and real migrations committed from day one.
2. **Planned** — port `amrs-project`'s `edgar` app (SEC/XBRL-to-ledger integration) as a self-contained optional module.
3. **Planned** — port `amrs-django`'s React frontend as DjangoERP's UI, rewired from its Token auth to this project's JWT convention.
4. **Future** — additional ERP modules (inventory, purchasing/sales, manufacturing, HR/payroll) building outward from this financial core.

`amrs-project`, `afms`, and `amrs-django` remain in place with pointers back to this repo; nothing has been deleted from them.
