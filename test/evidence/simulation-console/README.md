# Simulation console loads, signs in and shows the sandbox's books, agents and what-ifs — evidence

> **Feature:** `DJERP-013` (with `DJERP-011`, `DJERP-012`, `DJERP-014` seen through it) · **Scenario:** `verify/scenarios/simulation-console.yml` · **Generated by:** `node verify/runner.mjs --feature DJERP-013 --stamp --by agent` against a fresh database on `http://127.0.0.1:8766`, plus signed-in captures from a seeded sandbox on `http://127.0.0.1:8765`, both on 2026-11-20 (UTC) · **Result:** PASS on desktop and mobile

A visitor opening `/console/` on a fresh database gets a titled page ("Simulation console · DjangoERP"), a labelled JWT sign-in form, the console's sections hidden until sign-in, the skip link as the first Tab stop, and a refused sign-in reported inside the form ("No active account found…") rather than as an error page. All 21 steps passed at 1280×800 and 390×844, with no console errors and no horizontal scroll. The first run of this scenario failed at step 9 on both viewports: the section tabs were visible before sign-in, because the console's `display: flex` overrode the `hidden` attribute. A global `[hidden] { display: none !important; }` rule fixed it, and the failure screenshots were removed from the bundle.

The signed-in captures come from a scratch SQLite database seeded with `python manage.py simulate --ticks 45 --start 2027-01-01` and a throwaway accountant account (`analyst`) that exists only in that file, so no real credentials were used (`verify/verify.yml` `agent.never`). A Playwright session then signed in, stepped the clock with the console's own "+7" button (tick 55 → 62), hovered a chart, opened a goods-receipt trace from the activity feed, ran the "Add a production line for product line A" what-if, and signed in again in dark mode and on an iPhone 13 viewport. Across the session it saw no page errors or console errors, and no horizontal overflow at 1280 or 390 px. The crosshair tooltip listed every series at the hovered date (2 rows on the conversion-cost chart). The trace drawer showed both journal entries behind the receipt. The 30-tick what-if took 18.0 s with eager Celery, and both arms rolled back.

## Not covered

- Claude-driven agents in the browser: this sandbox had no `ANTHROPIC_API_KEY`, so every agent used the heuristic driver. The Claude path is covered by `simulation/tests.py` (`BrainTests`, `ClaudeDriverTests`) against a fake client that checks the request shape (model `claude-haiku-5-5`, structured output, low effort, no sampling parameters), clamping, the per-tick call budget, fallbacks and the AI cost posted to 6300.
- Long runs: the session covered 62 ticks, and the engine was separately run 60 ticks on another seed (7) with every guardrail holding on every tick; multi-year horizons were not exercised.
- Keyboard use of the charts was checked by script but not captured: focusing a chart showed its tooltip at the latest date (2027-03-04), two presses of ← moved it to 2027-03-02, and tabbing away hid it.
- Docker and PostgreSQL: this run used SQLite and `runserver`; the engine uses only ORM features both backends support, but no PostgreSQL run was made.
